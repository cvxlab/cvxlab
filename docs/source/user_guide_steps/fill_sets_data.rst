.. _fill-sets-data:

Fill sets data (model coordinates)
==================================

In this step, the user fills the sets data, defined as the model *coordinates*. 

Based on the Sets structure defined by the user in previous steps, according to 
the notation and conventions defined in :ref:`sets_definition`, the blank file 
``sets.xlsx`` (with a structure automatically generated) is now filled with the 
corresponding data.


Generic file structure
----------------------

**Excel** has been chosen as the sole coordinates input format, due to the fact 
that models are usually defined by several Sets, each characterized by many 
coordinates and filter/aggregation categories. Using a tabular format allows users to 
easily visualize and manage the data, and to use Excel functionalities (e.g., 
lookup functions, etc.).

Below, an example of the generic ``sets.xlsx`` file structure is shown.


.. list-table:: Generic structure of each set tab in ``sets.xlsx`` file.
   :header-rows: 1
   :widths: 20 20 20 10

   * - <set_name>_Name
     - <set_name>_<filter_name_#>
     - <set_name>_<aggregation_name_#>
     - ...
   * - <str>
     - <str>
     - <str>
     - <str>
   * - ...
     - ...
     - ...
     - ...


.. rubric:: Field descriptions and conventions

Each Excel **tab** corresponds to a specific set defined in the model. Each set 
tab is named as ``_set_<SET_NAME>``, where ``<SET_NAME>`` is the capitalized name 
of the set, as defined in the model settings. This naming convention makes it easy to 
identify the Set tables in the SQLite database. The ``_set_`` prefix 
(as well as other prefixes conventionally adopted elsewhere) are defined and 
customizable in :class:`cvxlab.defaults.Defaults.Labels`.

In each ``_set_<SET_NAME>`` tab, the user fills the set coordinates in the table above, 
structured as follows: 


.. list-table:: 
   :header-rows: 1
   :widths: 30 70

   * - Column name
     - Description
   * - ``<set_name>_Name``
     - This column is **mandatory**. Each row is filled with the actual coordinates of 
       the set. The column name is automatically generated by CVXlab and should not 
       be modified by the user.
   * - ``<set_name>_<filter_name_#>``
     - This column corresponds to filters of the Set. Only present if the model 
       includes filters for the set, and it is **optional** for the user to fill.
   * - ``<set_name>_<aggregation_name_#>``
     - This column corresponds to aggregation categories of the Set. Only present in 
       case the model includes aggregation categories for the set, and it is 
       **optional** for the user to fill.


Notes
-----

- There is no distinction between **Inter-problem sets** and **Dimensions sets** 
  in the ``sets.xlsx`` file. However, tabs for Inter-problem sets are expected to 
  present only the first column (i.e., the coordinates column), since this Set is 
  not expected to be filtered or aggregated.
- In running CVXlab models, it may be useful to update the sets data. Two cases 
  may occur:

  - For major updates, such as adding new sets or coordinates, other model 
    settings may be affected (e.g. how variables are defined or shaped). This may 
    require the SQLite database and input files to be re-generated to reflect the new 
    model structure. 
  
  - If *aggregation* categories need to be added without changing Sets and 
    related coordinates or filters, the Sets can be updated, reflecting changes in 
    SQLite databases, without re-generating the database and input files. This 
    can be achieved by using the API method :py:meth:`~cvxlab.Model.update_sets_tables`, 
    which updates the sets data without changing the model structure.
